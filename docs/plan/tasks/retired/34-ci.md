# 34 — CI

**Repo:** .
**Depends on:** nothing
**Owns:**
- .github/workflows/build.yml

## Goal
`mvn clean verify` runs on every push and pull request, so a test figure in a
PR is a check anyone can read rather than a claim the author makes.

## Context
- docs/architecture.md#building — the build needs a JDK 17 toolchain and `~/.m2/toolchains.xml`, which is not part of the repo. CI must provision it the way `.claude/hooks/session-start.sh` does for web sessions.
- pom.xml — `toolchain.jdk.version` is 17, `maven.compiler.release` is 8, and `maven-enforcer-plugin` requires Maven to run on JDK 9+. The toolchain is what compiles; the JDK running Maven is a separate thing.
- pom.xml — animal-sniffer's `java18` signature check and the javadoc doclint gate both run at `verify`, so `verify` is the phase CI must reach. `mvn test` would skip both.

## Acceptance
- [ ] A workflow runs `mvn clean verify` on push and on pull request against the default branch.
- [ ] It provisions a JDK 17 toolchain and writes `~/.m2/toolchains.xml` so `maven-toolchains-plugin` resolves. **Do not restate the version**: read it from the POM, as the session-start hook does, so the two cannot drift.
- [ ] The Maven dependency cache is keyed on the POMs, so an unchanged build does not re-download the plugin set.
- [ ] **The workflow is proved to fail on a real failure**, not assumed to. Break something locally, confirm the same command fails, restore. A green check nobody has seen go red is worth nothing, which is the lesson task 31 recorded.
- [ ] The job name and the check it produces are legible in a PR: a reviewer should see *what* ran without opening logs.
- [ ] No secrets, no publishing, no release steps. This task runs the build and nothing else.

## A judgement this task owes
This project has completed six milestones on local runs alone, and its PRs have
each asserted a test count on the author's word.

Report in the commit body whether CI agrees with the local figure on first run.
If it does not, the difference is a finding about the local environment, not a
CI problem to paper over.

## Out of scope
- Publishing, signing, or anything touching credentials — task 35, and even there only configuration.
- Matrix builds across JDKs. One toolchain is what the project supports; a matrix would assert something untrue.
- Coverage reporting, static analysis, or any new gate. The build already carries its own.
